### 4. MOTOR DE INGESTIÓN Y "CHANGE DETECTOR" (PUNTOS 18 Y 48)
El mayor reto legal es que los requisitos de Extranjería cambian (ej. Sentencias del Tribunal Supremo que anulan artículos, o reformas del Reglamento).
**Arquitectura del Change Detector:**

1.  **Crawler (Python/Playwright):** Se ejecuta semanalmente sobre URLs semilla (ej. `https://www.inclusion.gob.es/es/migraciones/`).
2.  **Hashing de Contenido:** Se extrae el texto limpio (usando `trafilatura`), se normaliza y se genera un hash SHA-256.
3.  **Comparación:** Si `hash_actual != hash_almacenado`, se dispara una alerta.
4.  **NLP / LLM Local:** Un modelo local (ej. `Llama-3-8B-Instruct` corriendo en Ollama) compara el texto antiguo y el nuevo, y genera un resumen de diferencias: *"Se ha modificado el tiempo mínimo de permanencia para el Arraigo Sociolaboral"*.
5.  **Acción:** El sistema marca los `LegalProcedure` afectados con la etiqueta `NEEDS_REVIEW` en el Panel de Administración y envía una alerta a los usuarios suscritos a ese trámite.

# PROYECTO: ECOSISTEMA "CUIDAR CONECTA"
## 0. MISIÓN Y FILOSOFÍA
Democratizar el conocimiento técnico y humano sobre el cuidado geriátrico y de pacientes crónicos. Transformar la intuición en **protocolos basados en evidencia**, y la carga emocional en **apoyo estructurado**. 

El núcleo filosófico se basa en tres pilares reales de la enfermería y geriatría moderna:
1. **Cuidado Centrado en la Persona (CCP):** No tratar "la enfermedad", sino a la persona con su historia.
2. **Política Nacional de Humanización (PNHAH - Brasil):** La clínica ampliada y el acogimiento.
3. **Seguridad del Paciente:** Prevención de Eventos Adversos (caídas, úlceras, infecciones, errores de medicación).

## 2. ARQUITECTURA DEL CONOCIMIENTO (LOS PROTOCOLOS)
Los protocolos no serán textos estáticos. Serán **Algoritmos de Cuidado (Care Algorithms)** versionados como código abierto (Git). Cada protocolo tendrá un nivel de evidencia (Sistema GRADE) y fecha de revisión clínica.

### MÓDULO A: PROTOCOLOS CLÍNICOS Y TÉCNICOS
1.  **Prevención y Manejo de Lesiones por Presión (UPP):**
    *   *Evaluación:* Escala de Braden adaptada.
    *   *Acción:* Protocolo de cambios posturales (regla de los 30 grados), selección de Ácidos Grasos Hiperoxigenados (AGHO) vs. apósitos hidrocoloides.
2.  **Seguridad en la Alimentación y Disfagia:**
    *   *Evaluación:* Test de deglución (EVA).
    *   *Acción:* Modificación de texturas (néctar, miel, pudin), postura de seguridad (mentón al pecho), prevención de neumonía por aspiración.
3.  **Movilización y Biomecánica (Cero Lesiones para el Cuidador):**
    *   *Técnica:* Uso de cinchas de transferencia, cama articulada, principios de palanca. Prevención de lumbalgias en el cuidador.
4.  **Manejo de Vías y Dispositivos:**
    *   *Protocolos:* Cuidado de Sonda Nasogástrica (SNG), Gastrostomía (GTT), Sonda Vesical, y Oxigenoterapia domiciliaria.
5.  **Higiene y Confort:**
    *   Baño en cama (técnica de las 9 toallas), prevención de dermatitis asociada a incontinencia (DAI).

### MÓDULO B: PROTOCOLOS NEUROCOGNITIVOS (DEMENCIAS)
1.  **Manejo del Síndrome Crepuscular (Sundowning):** Protocolos de iluminación, rutinas y reducción de estímulos.
2.  **Terapia de Validación vs. Orientación a la Realidad:** Cuándo corregir al paciente y cuándo entrar en su realidad para evitar la agitación.
3.  **Manejo de la Deambulación Errática y Riesgo de Fugas:** Seguridad ambiental en el hogar.

### MÓDULO C: APOYO PSICOSOCIAL Y FAMILIAR
1.  **El Duelo Anticipatorio y los Cuidados Paliativos:** Cómo hablar de la muerte, control de síntomas (dolor, disnea) en casa.
2.  **Prevención del Síndrome del Cuidador Quemado (Burnout):** Protocolo de "Respiro Familiar", gestión de la culpa y redes de apoyo.
3.  **Adaptación del Hogar (Arquitectura del Cuidado):** Eliminación de barreras, iluminación, barras de apoyo, antideslizantes.

## 3. LA PLATAFORMA WEB (OPEN SOURCE & WIKI-HEALTH)
La web funcionará como el **"GitHub del Cuidado"**. Los profesionales de la salud (enfermeros, fisioterapeutas, médicos) podrán hacer *Pull Requests* (solicitudes de mejora) a los protocolos, que serán revisados por el comité editorial de Marcia.

*   **Stack Tecnológico:**
    *   **Frontend:** Next.js + Astro (para carga ultrarrápida en zonas rurales con 3G).
    *   **CMS:** MDX (Markdown + JSX). Los protocolos se escriben en Markdown, permitiendo insertar componentes interactivos (calculadoras de riesgo, sliders de dosis).
    *   **Base de Datos:** PostgreSQL (para usuarios y progreso) + Graph Database (Neo4j) para cruzar síntomas con protocolos.
    *   **Control de Versiones:** Git. Cada cambio en un protocolo médico queda registrado: *Quién lo cambió, cuándo, y con qué evidencia científica.*
*   **Modo "Emergencia" (Acceso Rápido):** Botón rojo permanente en la UI. Si un paciente se atraganta o se cae, la interfaz cambia a modo alto contraste con instrucciones paso a paso (Maniobra de Heimlich, evaluación de traumatismo craneal) y el botón de llamar a emergencias (SAMU 192 / 112).

## 6. MODELO DE DATOS (ESQUEMA POSTGRESQL)
Estructura para soportar la complejidad clínica y el versionado.

```prisma
model Protocol {
  id            String   @id @default(cuid())
  slug          String   @unique // ej: prevencion-ulceras-presion
  title         String
  category      Category // CLINICAL, COGNITIVE, PSYCHOSOCIAL, EMERGENCY
  targetAudience Audience[] // FAMILIAR, NURSING_ASSISTANT, NURSE
  evidenceLevel String   // GRADE A, B, C
  steps         Step[]
  warnings      Warning[]
  versions      Version[]
  createdAt     DateTime
  updatedAt     DateTime
}

model Step {
  id            String   @id @default(cuid())
  protocolId    String
  protocol      Protocol @relation(fields: [protocolId], references: [id])
  order         Int
  instruction   String   // Texto claro y directo
  mediaUrl      String?  // Video o infografía
  rationale     String?  // El "por qué" científico (colapsable)
}

model Warning {
  id            String   @id @default(cuid())
  protocolId    String
  protocol      Protocol @relation(fields: [protocolId], references: [id])
  type          WarningType // RED_FLAG, CONTRAINDICATION, MYTH
  message       String
}

enum WarningType {
  RED_FLAG       // Ir a urgencias inmediatamente
  CONTRAINDICATION // No hacer esto nunca
  MYTH           // Creencia popular falsa
}
```
